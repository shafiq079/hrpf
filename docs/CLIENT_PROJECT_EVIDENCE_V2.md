## Run from repository root

The original project seeds must already exist. Use the same private development configuration as the first batch: Mongo replica-set support, Cloudinary credentials, `NODE_ENV=development`, `CLOUDINARY_NAMESPACE=hrpf/dev`, and `SEED_ACTOR_EMAIL` for an active content administrator/editor.

```bash
git switch development
git pull --ff-only origin development
npm --prefix backend run seed:project-evidence-v2
npm --prefix backend run seed:project-evidence-v2 -- --database
npm --prefix backend run seed:project-evidence-v2 -- --apply
```

No flags verify files offline. `--database` is read-only. `--apply` updates existing rows and uploads/binds media. No live database/Cloudinary settings were used during implementation. If working inside `backend/`, omit `--prefix backend`.

For a database that has not applied the first evidence batch, run `seed:project-evidence -- --apply` first. Its original manifest/checkpoints remain unchanged. The v2 updater recognizes valid first-batch and original homepage-detail checkpoints, so unchanged managed text can advance while subsequent admin edits win. Each project commits atomically with a new v2 checkpoint and public-cache invalidation. It never recreates deleted entries or republishes withdrawals.
