## Publication decisions

- Publish concrete documented activities, complaints, research, petitions and
  small welfare interventions. Describe which work HRPF did and which was done
  by a public-service provider.
- Completed means the recorded action was completed: a report or awareness
  statement being published does not mean its recommendations were implemented.
  Ongoing is the last documented unresolved stage, not confirmation of continuous
  operation today. Each project provides a dated period and limits on outcomes.
- Do not publish victim names, child locations/FIR details, contact information,
  graphic descriptions, identifying case photos or contested accusations as
  findings. No original case annexes are uploaded with this seed.
- Do not invent beneficiary totals, funding, schools built, workshops held,
  legal victories, medical services or partnerships. Empty optional sections
  stay empty. The school contribution is attributed to the chairman.
- Use the already-reviewed annual-report covers, with accurate alt text. There
  is no confirmed photograph for most interventions; unrelated archive people
  are not labelled as participants. Admins can replace a cover with a verified
  project photograph later.
- Keep references and source-review notes in internal evidence files and
  sourceReferences. Public narratives omit technical archive captions and source
  footnotes. The public API excludes internal references.

Existing shelter, sanitation and childhood-vaccination projects are preserved;
repeat mentions are consolidated, not imported again. RTI requests, press-safety
cases, canal-pollution representations, trafficking material and electricity
infrastructure updates are each grouped where they describe the same thematic
effort. School descriptions repeated on pages 13/16 and LinkedIn are one project.

The older Myanmar petition and 2018 journalist petition remain research leads,
not automatically published: their dates precede the profile's stated operating
history and the starter profiles were blocked. The August 2026 missing-migrants
case is also held pending original correspondence. The profile's proposed jail
monitoring visits and PEF focal-person designation establish preparation, not
completed visits or a delivered school programme. The reports' additional
incident statements are not individually converted into victim-based project
pages. General goals for shelter, rehabilitation, interfaith events, training and
international partnerships are not invented as delivered programmes.

Other documented welfare expenditure (medicine/clothing) lacks enough dated
programme detail for separate full project pages. Livestock-health, river-rescue
and police mental-health statements remain research leads rather than fabricated
service-delivery projects. They can be added when scope and source dates are
confirmed. The machine-readable review inventory and individual evidence files
record the catalog's provenance and explicit outcome limits.

## Import and reader integration

From the repository root, using the existing private development configuration:

```bash
npm --prefix backend run seed:work-projects
npm --prefix backend run seed:work-projects -- --database
npm --prefix backend run seed:work-projects -- --apply
```

The first command verifies all source/cover checksums offline, without connecting
to a database or uploading. The second is a read-only database plan. The third
creates and publishes the new managed project records and uploads the covers.
This does not recreate users, replace existing projects, reset the database or
reseed the homepage. Requires the existing private backend/.env, an active
editor/admin named by SEED_ACTOR_EMAIL, NODE_ENV=development, hrpf/dev namespace,
MongoDB transaction support and configured Cloudinary credentials. No credentials
are included in the catalog and no live NGO database was used for verification.

The create-only importer checks deterministic IDs, source checksums and unique
slugs. Later admin edits, withdrawals, deletions and unmanaged slug collisions
are preserved. Interrupted draft/uploads recover their staged assets. Changed
sources are reported instead of overwritten; conflicts/source changes exit 2.
Publication checks the actor again, binds owned clean assets transactionally,
adds an audit record and invalidates public caches through the existing revision
counter. Reruns don't upload or publish the same completed batch again.

Projects remain English source content and use the existing website translation
widget. No duplicate Urdu-only records or generated translations are imported.
Related fields use the existing comma-separated focusArea property, preserving
schema/API compatibility. Admin help explains the format. Public field filters
match the whole field and apostrophe variants; the Projects explorer now presents
individual field options rather than combinations. Field links open the explorer
with the relevant filter selected. All eight subpages use the general approach
layout and managed project feed; the last two no longer show prototype projects,
statistics or testimonials. The explorer currently reads up to 48 projects,
which covers this catalog plus the three existing entries; server pagination is
needed if the published collection later exceeds that limit.

Catalog: backend/seed/work-projects-manifest.json. Provenance inventory:
docs/WORK_PROJECT_RESEARCH.json. Per-project evidence:
backend/seed/home-assets/progress reports/work-project-evidence/.
