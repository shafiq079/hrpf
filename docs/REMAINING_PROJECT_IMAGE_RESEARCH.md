## Research scope and limits

Public searches used project titles, distinctive report wording, HRPF's full name, `hrpfpk` and the chairman's name. Relevant Facebook post identities were resolved from indexed links or an actual archived post identifier, then their public metadata/media were inspected. Matching LinkedIn narratives, the Change.org petition, the official website and the [public HRPF post archive](https://www.findglocal.com/PK/Mianwal/1500163953642649/Human-Rights-Protection-Foundation-Pakistan) were checked. The archive's Minorities Day image URL returned 404; the original Facebook post supplied the usable copy instead.

Facebook exposed preview metadata for the two selected posts, not their complete bodies or albums. LinkedIn's public profile feed was unavailable, although the specific women's statement was accessible. No private account/session, sign-in bypass or full video transcript was used. Exact post/topic matches are distinguished from comments, tagged pages and unrelated organisations with similar names. The women's statement and sensitive child/overseas media were inspected but are not committed.

The two new files are unchanged published JPEG copies in `backend/seed/home-assets/progress reports/client-project-evidence-2026-10-batch3/`. `backend/seed/client-project-evidence-v3.json` records canonical post URLs, image roles, alt text, dimensions, byte lengths and SHA-256 hashes. Expiring social CDN links are not used by the website. Both entries are marked `partial` because full Facebook retrieval was unavailable. Existing sourced project text stays intact; new outcomes, dates, event attendance and named allegations are not inferred from thumbnails.

## Apply from repository root

```bash
git switch development
git pull --ff-only origin development
npm --prefix backend run seed:project-evidence-v3
npm --prefix backend run seed:project-evidence-v3 -- --database
npm --prefix backend run seed:project-evidence-v3 -- --apply
```

If already inside `backend/`, omit `--prefix backend`. No flags verify the two local files offline; `--database` is a read-only plan. `--apply` uses your existing private development MongoDB/Cloudinary configuration and active `SEED_ACTOR_EMAIL`, with `NODE_ENV=development` and `CLOUDINARY_NAMESPACE=hrpf/dev`. The existing seed-owned published projects must already exist. No new project is created; this image-only batch does not require reapplying older evidence revisions.

Expected first application: two `updated` results. A missing cover receives the matching asset; an existing admin cover is retained and the image goes into the gallery. Existing text, work-page selections, documents and other media stay intact. Deleted/withdrawn/unmanaged entries and full galleries are preserved. A repeat produces `already-updated` and does not upload again or restore a subsequently removed image. File hashes are verified before writes, and assets/checkpoints/cache updates follow the existing transactional evidence workflow.

No live database or Cloudinary writes were performed during implementation. Check both project cards/detail pages and their admin cover/gallery on desktop/mobile after applying. The portrait poster/still will crop in landscape cards; inspect the full asset on the project page. The eight other projects remain editable through the existing admin panel.
